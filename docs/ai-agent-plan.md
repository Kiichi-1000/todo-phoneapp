## 1. ビジョンと位置付け

### コンセプト

> 「**話しかけるだけで、ToSche が動く。**」

ToSche のすべての主要機能（ワークスペース・スケジュール・ルーティーン・統計）に対して、自然文で指示・参照できる AI を提供する。手動操作の代替ではなく、**手動操作の上位互換**を目指す。

### ペルソナ別の価値

| ペルソナ | 価値 |
|---------|-----|
| **忙しい朝**, 出勤前 | 「経費精算と歯医者予約のリマインドを今日中に」と一言で2件登録 |
| **会議中**, スマホを見られない | iPad に Apple Pencil で書き → AI が文字認識してタスク化 |
| **週末**, 来週の計画 | 「来週月曜の朝9時から1時間、企画会議を入れて」 |
| **振り返り**, 月末 | 「今月の達成率と、未完了が多いカテゴリを教えて」 |
| **習慣化中**, 夜寝る前 | 「今日の朝のルーティーン、やった分だけチェックして」 |

### 競合との差別化

| 機能 | ToSche AI | ChatGPT | Things AI | Todoist AI |
|-----|----------|---------|-----------|------------|
| 自然文タスク追加 | ✓ | △ (連携必要) | ✗ | ✓ |
| 円グラフスケジュール操作 | **✓ 独自** | ✗ | ✗ | ✗ |
| ルーティーン管理 | **✓ 独自** | ✗ | ✗ | ✗ |
| 4分割エリア理解 | **✓ 独自** | ✗ | ✗ | ✗ |
| 手書き → タスク化 | ✓（iPad） | ✗ | △ | ✗ |
| 達成率の文脈理解 | **✓ 独自** | ✗ | ✗ | △ |

## 3. フェーズ別実装計画

機能カタログを **MVP / 拡張 / 上級** の3フェーズに分け、リリース計画と紐付ける。

### Phase 1 — MVP（v2.0 リリース時）

**目的**: 「AI で日常タスクの基本操作が完結する」状態を作る。
**含む機能**: 重要度 ★★★ + 一部 ★★（基盤）

| カテゴリ | 含む機能 |
|---------|---------|
| A. タスク | A1, A2, A3, A4, A5（要確認）|
| B. スケジュール | B1, B3, B5（要確認）, B7（基本）|
| C. ルーティーン | C1, C2 |
| D. 統計 | D1, D2 |
| E. 検索 | E3 |
| F. 基盤 | F1, F2, F4 |
| **AI ツール総数** | **約 12個** |

**リリース基準**:
- 9割の自然文指示が成功（ターゲット文の検証セット 100件で90件成功）
- 1ターン3秒以内に応答開始
- 月の AI コストが平均ユーザーで¥500以内

### Phase 2 — 拡張（v2.1, MVP公開2〜4週間後）

**目的**: 「AI で凝った操作までできる」状態を作る。
**含む機能**: 残りの ★★ + ★ の半分

| カテゴリ | 含む機能 |
|---------|---------|
| A. タスク | A6, A7, A8, A9, A10 |
| B. スケジュール | B2, B4, B6, B8, B9 |
| C. ルーティーン | C3, C4, C5, C6 |
| D. 統計 | D3, D4 |
| E. 検索 | E1, E2, E4 |
| F. 高度 | F3, F5 |
| **追加 AI ツール** | **約 8個** |

### Phase 3 — 上級（v2.2 〜 v3.0）

**目的**: 入力モダリティ拡張、プロアクティブ AI 化。

| カテゴリ | 含む機能 |
|---------|---------|
| B | B10（繰返予定） |
| D | D5（コーチング） |
| F | F6（手書き）, F7（音声） |
| その他 | 通知時の AI サマリ、夜寝る前の振り返り通知 |

## 4. 技術アーキテクチャ

### 全体図

```
┌────────────────┐                   ┌──────────────────┐
│ React Native   │                   │  Anthropic       │
│ (iPhone/iPad)  │                   │  Claude API      │
│                │                   │  (Haiku 4.5)     │
│ AI Chat Tab    │                   └────────▲─────────┘
│ TokenBalance   │                            │
└───────┬────────┘                            │
        │ POST /ai-chat (JWT, messages)       │
        │ ← SSE stream                        │
        ▼                                     │
┌─────────────────────────────────────────────┴───────┐
│ Supabase Edge Function `ai-chat`                    │
│  - JWT検証 → user_id 確定                           │
│  - サブスク/クーポン/試運転チェック                  │
│  - トークン残高チェック                              │
│  - Anthropic 呼出（Tool Use + Streaming + Cache）   │
│  - Tool 実行ループ                                   │
│  - SSE で順次クライアントに返却                      │
│  - 終了時に消費量を ai_token_transactions へ記録      │
└──────────┬──────────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────┐
│ Supabase Postgres (RLS)           │
│  - workspaces / todos / schedules │
│  - user_settings / routine_*      │
│  - ai_token_balances              │
│  - ai_token_transactions          │
│  - ai_promo_codes / redemptions   │
└──────────────────────────────────┘
```

### モデル選定

| 用途 | モデル |
|-----|-------|
| 標準対話 | `claude-haiku-4-5`（速い・安い） |
| 複雑推論（Phase 3） | `claude-sonnet-4-6`（オプション切替） |
| 手書き OCR（v3） | iOS 標準 Vision Framework（無料・オンデバイス） |
| 音声入力（v3） | OpenAI Whisper API or iOS 標準 Speech Recognition |

### プロンプトキャッシュ戦略

- **System prompt + ツール定義 + ユーザー文脈**（言語・タイムゾーン）を `cache_control` でキャッシュ
- TTL 5分 → 連続会話でほぼ毎ターンキャッシュヒット
- 入力コスト 90% 削減

### Tool Use ループ

```
ユーザー入力
  ↓
Claude (text + tool_use)
  ↓ tool_use があれば
Edge Function が Tool 実行 (Supabase に対する CRUD)
  ↓
Tool 結果を Claude に返す
  ↓
Claude (text or 次の tool_use)
  ↓ ループ
最終的に text のみ返ってきたら SSE 終了
```

最大 5回ループで打ち切り（暴走防止）。

## 6. UX 設計

### 6.1 配置

- 既存タブバーに **「AI」タブを追加**
  - iPhone: 5 → 6 タブ。スペース苦しい場合は「ルーティーン」をサブメニュー化
  - iPad: サイドバーに常時表示

### 6.2 チャット画面の構成

```
┌─────────────────────────────┐
│ ⬅ AI アシスタント        🔄 │  ← ヘッダー（履歴クリア）
│ 残り 432円分                │  ← トークン残高（残20%以下で警告色）
├─────────────────────────────┤
│                              │
│  ユーザー: 明日10時から会議   │  ← 吹き出し（右）
│                              │
│  AI: 明日 5/9 (金) 10:00 から│  ← 吹き出し（左、ストリーミング）
│  予定を作成しました ✓        │
│                              │
│  ┌─────────────────────────┐│  ← ツール実行結果カード
│  │ 📅 予定                  ││
│  │ 5/9 10:00 - 11:00       ││
│  │ 「ミーティング」          ││
│  │ ↗ スケジュール画面で開く ││
│  └─────────────────────────┘│
│                              │
├─────────────────────────────┤
│ メッセージを入力...    [送信]│  ← 入力欄
└─────────────────────────────┘
```

### 6.3 確認ダイアログのパターン

操作種別ごとに確認の有無を明示:

| 操作 | 確認 |
|-----|-----|
| 単一作成（task / schedule） | 不要、結果カード表示 |
| 単一更新 | 対象が一意なら不要、複数候補なら確認 |
| **削除（任意）** | **必ず確認** |
| バルク操作（3件以上） | **必ず確認** |
| 過去データの編集 | 警告（「過去日付ですが進めますか?」） |

### 6.4 トークン残高の表示

- チャット画面上部に常時表示（「残り ¥432分」）
- 残20%以下: オレンジ色 + 「上位プランへ」リンク
- 残ゼロ: 入力欄をグレーアウト + 上部に「今月のトークンを使い切りました」案内

### 6.5 試運転期間の表示

- v2.0 リリース後14日間: チャット画面上部に「**🎉 試運転期間中（残り N 日）**」バッジ
- 期間終了 3日前: 「あと3日で試運転終了です。プランを選んでください」のお知らせ
- 期間終了後: 入力できない、アップグレード画面へ誘導

### 6.6 クーポン入力導線

- **設定 → サブスクリプション → 「クーポンコードを入力」**
- 入力 → 検証 → 「✓ クーポンが適用されました（YYYY/MM/DD まで使い放題）」
- 適用済みクーポンは設定画面で一覧表示

## 10. リスクと対策

| リスク | 致命度 | 対策 |
|-------|-----|-----|
| AI コスト暴走 | 高 | トークン残高ハード上限・1日¥200上限・1ターン上限 |
| ツールが架空ID生成 | 高 | RLS で他人触れない + 不存在IDはエラーで再試行誘導 |
| 自然文の誤解釈 | 中 | F2 確認ダイアログ + 復唱確認 |
| プロンプトインジェクション | 中 | ツール内ユーザーIDはサーバー固定、他ユーザー指示拒否 |
| Anthropic API 障害 | 中 | エラー表示 + 通常UIへ誘導 |
| 為替変動 | 中 | 内部レート¥150/$四半期見直し（規約明記）|
| ストア審査リジェクト | 中 | 試運転2週間は「促進キャンペーン」と説明 |
| RevenueCat 障害 | 低 | `customerInfo` キャッシュで24h 猶予 |
| トークン残高整合性 | 中 | DB トランザクションで balance/transaction を原子的に更新 |
| クーポン悪用 | 中 | UNIQUE(user_id, code) + max_redemptions + 期限 |

## 11. 受け入れ基準（v2.0 / Phase 1 リリース判定）

### 機能基準

1. 「明日10時から会議入れて」で予定が作成され、ワークスペースとスケジュールに反映される
2. 「経費精算のタスク追加」でタスクが作成される
3. 「歯医者の予定キャンセル」で確認ダイアログ → 削除実行
4. 「今日の予定教えて」でリスト表示
5. 「今月の達成率は?」で数値表示
6. 削除など破壊的操作は必ず確認される
7. 試運転期間中、ユーザー全員が AI を無料で利用できる
8. 試運転終了後、未契約ユーザーは AI が使えなくなる
9. クーポンコード入力で無料利用権が付与される
10. AI ライト/スタンダード購入後、即座にトークン残高が付与される
11. 月初にトークンが新規付与され、前月分は繰越される
12. 残高ゼロで送信不可、上位プラン誘導が表示される

### 品質基準

13. 検証セット 100件中 90件以上成功
14. 1ターンの初回応答が3秒以内
15. ツール実行ループが10秒以内に完了
16. 1ユーザー月次平均 AI コストが ¥500 以下（ヘビー上限ユーザー除く）

### セキュリティ基準

17. 他ユーザーの ID を指定しても操作不可
18. プロンプトインジェクション耐性確認
19. API キーがクライアントに漏れない（Edge Function 内のみ）
