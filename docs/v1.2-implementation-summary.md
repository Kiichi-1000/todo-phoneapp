## 2. What v1.2 ships

The big themes vs. v1.1 ("planner only, free"):

1. **AI Assistant tab** — Claude-powered chat that creates/edits tasks, schedules, routines, and goals through natural language.
2. **Goal Coach** — dedicated AI screen that breaks long-term goals into yearly → half-year → monthly → daily milestones.
3. **Voice input** — Google Cloud Speech-to-Text for hands-free task capture (Standard/Pro only).
4. **6 auto-renewable subscriptions** (3 tiers × monthly/yearly) via RevenueCat → Apple IAP.
5. **100-page free tier** — users get up to 100 "used workspaces" free; beyond that, any subscription unlocks unlimited creation.
6. **Custom dark Paywall** — replaces the RevenueCatUI template. Reads `package.priceString` directly from StoreKit for correct JPY display on Japanese storefronts.
7. **Privacy consent modal** — explicit disclosure before any AI feature runs (what's sent to Anthropic, what's NOT sent). Apple guideline 5.1.1 compliance.
8. **Goals view** in the workspace tab (any-tier-subscriber, AI gates separately).
9. **Sign in with Apple** — first-class alongside Email and Google.
10. **Polished Japanese / English localization** across settings, schedule, routine, workspace, statistics, FAQ, terms, privacy.

## 4. Subscription tiers (the core business model)

### Tier matrix

| Tier | Monthly (税込) | Yearly (税込, 10% off) | Includes AI | Beyond 100-page tier |
|---|---:|---:|:---:|:---:|
| **ToSche** (basic) | ¥300 | ¥3,240 | ❌ | ✅ |
| **AI Standard** | ¥1,200 | ¥12,960 | ✅ standard token allowance | ✅ |
| **AI Pro** | ¥2,000 | ¥21,600 | ✅ expanded token allowance | ✅ |

> AI token grant amounts are an internal/business secret and **must not be exposed in the UI**.
> They are set in `supabase/functions/monthly-token-grant/index.ts` (`PLAN_GRANT_YEN`).
> v1.2 values: `basic: 0` (no AI), `standard: 400`, `pro: 700` (yen-denominated monthly grant).

### Product IDs (Apple side)

| Plan / Cycle | iOS Product ID | RC package lookup |
|---|---|---|
| Basic monthly | `ToSche.std.1.2` | `$rc_custom_basic_monthly` |
| Basic yearly | `tosche_basic_yearly` | `$rc_custom_basic_yearly` |
| Standard monthly | `ToSche.AI.std.1.2` | `$rc_custom_standard_monthly` |
| Standard yearly | `tosche_ai_standard_yearly` | `$rc_custom_standard_yearly` |
| Pro monthly | `ToSche.AI.Pro.1.2` | `$rc_custom_pro_monthly` |
| Pro yearly | `tosche_ai_pro_yearly` | `$rc_custom_pro_yearly` |

### Token economy

- Each subscription month, the user is granted a per-tier yen-denominated AI usage allowance (`ai_token_balances.current_grant_yen`).
- Unused balance carries over **once** (to the next month, then expires).
- Each AI chat / Goal Coach interaction deducts cost from the user's effective balance (sum of current grant + non-expired carryover).
- When balance < ~¥1.5 (one turn floor) → `ai-chat` returns 402 `insufficient_balance` → client routes user to `/paywall?context=ai`.

| Voice input to AI | ❌ | ❌ | ✅ | ✅ |
| AI token allowance | none | none | standard | expanded |

### Helper functions (client-side, `lib/aiAccess.ts`)

| Function | Returns true for | Used by |
|---|---|---|
| `checkAiAccess(userId)` | Standard / Pro (active) + active promo + release-wide trial | AI tab gate, Goal Coach gate |

## 7. Edge Functions

Located in `supabase/functions/`.

| Function | Trigger | What it does | Auth |
|---|---|---|---|
| `ai-chat` | Client POST | Claude streaming + tool use loop. Checks access + balance before invoking. Tools defined in `tools.ts` (CRUD todos/schedules/goals). Costs deducted from `ai_token_balances` after each turn. | User JWT (RLS) |
| `goal-coach` | Client POST | Singleton conversation per user (`mode='goal_coach'`). Server reconstructs full history from DB on each turn → fed to Claude with prompt caching. | User JWT |
| `transcribe-audio` | Client POST audio | Forwards audio to Google Cloud Speech-to-Text, returns transcript. Audio not persisted. | User JWT |
| `revenuecat-webhook` | RC webhook | INITIAL_PURCHASE / RENEWAL / CANCELLATION / EXPIRATION / BILLING_ISSUE / PRODUCT_CHANGE / UNCANCELLATION → upserts `user_subscriptions`. Sets `next_grant_at` to trigger monthly token batch. | Shared secret `REVENUECAT_WEBHOOK_AUTH_HEADER` |
| `sync-subscription` | Client POST (post-purchase) | Bridges Apple-side purchase confirmation → RC webhook latency. Reads CustomerInfo from request and immediately marks the user as active. Client calls this from `purchasePackage()` success path. | User JWT |
| `monthly-token-grant` | Supabase Cron (hourly) | Finds users with `next_grant_at <= now() AND status IN ('active','trialing')`. For Basic → only rolls `next_grant_at` forward (no token grant). For Standard/Pro → expires past-due carryover, moves current grant to carryover, grants new month's allowance, logs all transactions. | Bearer `CRON_SHARED_SECRET` |
| `redeem-promo` | (deprecated for v1.2) | Originally redeemed coupon codes for free AI access. Removed from UI per Apple 3.1.1 ruling. Endpoint still exists but is unreferenced. | User JWT |

## 9. Paywall — design and implementation notes

### Why custom (not RC dashboard)

The RC `RevenueCatUI.Paywall` template displays prices via its own resolver, which on this app's setup
sometimes picked the Test Store (USD) variant of a package instead of the Apple Store JPY one. That
caused the visible "USD on Japanese device" bug. The custom paywall reads `pkg.product.priceString`
directly from `getOfferings()` — the same StoreKit-localized string Apple's payment sheet uses — so
the displayed price is guaranteed to match what the user is actually charged.

### Hero

Layered composition (no photo asset bundle initially, but a JPG hero was added late):
1. 5-stop vertical `LinearGradient`: deep night → violet twilight → dusk magenta → warm sunset orange → city-horizon shadow.
2. Diagonal yellow→pink→violet "sun glow" overlay on the upper-right.
3. SVG building silhouettes in two layers (distant semi-transparent navy, near-black foreground).
4. ~65% of a deterministic 5px window-grid pattern is lit (amber dots, LCG-seeded so the pattern is stable across rebuilds).
5. `assets/images/paywall-city.jpg` (1200×801) replaces the SVG fallback when the asset is present.

### Card layout

- 3 monthly tier cards in a row (Basic green / Standard blue / Pro purple). "おすすめ" badge on Pro.
- 3 yearly cards (compact, with "10% OFF" badge and per-month equivalent pill) in a row below.
- Feature comparison table below.
- Bottom CTA bar: gradient indigo→violet button + Restore link.
- 3 assurance badges: "100ページまで無料" / "いつでもキャンセル可能" / "安全な決済".

### Feature copy rule

The actual AI credit yen amounts (¥400 / ¥700 per month) are an internal-business-secret. The UI uses
non-specific labels: "毎月のAI利用枠付き" and "Standard より余裕のあるAI利用枠". The comparison table
uses "AI利用枠: 標準 / 拡張" (qualitative, not quantitative).

### Why no "7-day trial" badge

ASC has no introductory offer configured on these subscription products. Displaying a trial label
without the Apple-side configuration would violate guideline 2.3.2 / 3.1.2. v1.3 should configure
ASC introductory offers first, then add the badge.

## 10. Apple App Review — v1.2.0 rejection remediation

Apple rejected the initial v1.2 (build 34) for four guideline violations. v1.2 build 42 addresses all four:

| Guideline | Apple's note | How we fixed it |
|---|---|---|
| 2.1.0 — App Completeness | "we cannot locate the In-App Purchases" | App Review Notes now describes both UI paths to the paywall (AI tab → upgrade; Settings → AI Subscription → View Plans). All 6 IAPs are now attached to the version. |
| 2.3.2 — Accurate Metadata | "Your promotional image is the same as the app's icon" | Replaced with 6 unique 1024×1024 editorial-style promotional images (one per subscription product). User uploads them manually before final submit. |
| 3.1.1 — Payments / In-App Purchase | "the app uses coupon code to unlock or enable AI feature" | Removed promo-code UI from `app/(tabs)/settings.tsx`. Subscription unlock is now exclusively via Apple IAP. |
| 5.1.1 / 5.1.2 — Privacy | "does not clearly explain what data is sent" | Added `components/ai/AIConsentModal.tsx`. First-launch of the AI tab presents an explicit consent screen listing what is/isn't sent and to whom (Anthropic, PBC, USA). Privacy Policy section 4-2 mirrors the disclosure. |

## 13. Known constraints / v1.3 backlog

Things shipped intentionally incomplete or with documented compromises:

| Item | Why deferred | Path forward |
|---|---|---|
| 100-page free-tier enforcement is **client-side only** | The gate lives in `WorkspacePage.ensureWithinFreeLimitForFirstTask`; a determined user calling `INSERT` directly against Supabase via the service-role-less client can still bypass. | Add a Supabase RLS policy with WITH CHECK that counts distinct `workspace_id` in `todos` for the user before allowing insert when no active subscription exists, or a `BEFORE INSERT` trigger. |
| `checkWorkspaceCreationAccess` fetches `select('workspace_id')` for all the user's todos | Acceptable up to a few thousand todos; expensive on power users. The gate runs only when `todos.length === 0` on a given workspace, so frequency is bounded. | Replace with a Postgres function `count_used_workspaces(uid)` exposed via Supabase RPC. |
| Cross-device data sync is **fetch-on-focus, not realtime** | `useFocusEffect` re-fetches when tabs/dates change. Supabase Realtime channels are not used. | Add `supabase.channel().on('postgres_changes', ...)` for todos/schedules/goals in `WorkspacePage` / `GoalView`. Power use case: same user on iPhone + iPad simultaneously. |
| Data Export **not implemented on iOS** — entry hidden | Web has working Blob download; iOS native path needs `expo-sharing`. We hide the entry on `Platform.OS !== 'web'` for v1.2 to avoid showing a non-functional control. | Wire `expo-file-system` (write JSON to `FileSystem.cacheDirectory`) + `expo-sharing.shareAsync(uri)`. Remove the Platform guard. |
| No ASC introductory offer (trial) | Marketing reference design includes "7-day trial" badge, but ASC products have no `Introductory Offer` set. | Configure 7-day free trial in ASC for each of the 6 products, then add the trial badge to the assurance row in `paywall.tsx`. |
| RC paywall (dashboard-managed) is **published but unused** | After switching to custom code paywall, the dashboard paywall `pwc5c19d6a50724c52` still exists but the app never invokes `RevenueCatUI.Paywall`. | Either archive the dashboard paywall, or keep it as a fallback for future A/B testing via remote config. |
| `redeem-promo` Edge Function exists but the UI was removed | Apple flagged the promo-code redemption flow under 3.1.1. We removed the UI but left the server endpoint to avoid breaking historical redemptions. | Either fully decommission the function or re-enable a properly-Apple-compliant flow in v1.3+ (e.g., Offer Codes via ASC). |
| Debug telemetry was removed late | Several files were posting to `http://127.0.0.1:7260/ingest/...` (a dev-only collector). Removed in `c29767c` but worth keeping an eye on regressions. | Future debug instrumentation should go through a flag-gated logger module, not direct `fetch()`. |

## 14. Operating playbook (cheat-sheet)

### Re-deploy a single Edge Function after a code change
```bash
cd /Users/tsukuikiichi/Documents/todoapp-main
supabase functions deploy ai-chat                    # or any function name
```

### Trigger a new production build (and auto-submit)
```bash
eas build --platform ios --profile production --auto-submit --non-interactive
# Monitors: tail -f /tmp/eas-build-N.log
```

### Attach a build to v1.2 in ASC (when EAS auto-submit isn't enough)
1. Open https://appstoreconnect.apple.com/apps/6761228359/distribution/ios/version/inflight
2. Scroll to ビルド section.
3. Hover the existing build's row → red minus → confirm removal.
4. Click ビルドを追加 → select the new build's radio → 完了.
5. Click 保存 (top right).

### Replace an existing RC paywall via API (AI editor)
```typescript
mcp__revenuecat__edit-paywall-ai({
  project_id: 'projbaaa1929',
  paywall_id: 'pwc5c19d6a50724c52',
  message: '<your instructions>',
  codebase_context: '<short context>',
  app_context: { ... },
})
// Then poll get-paywall-ai-task with the returned task_id.
// Then publish via the RC dashboard (no API endpoint).
```

### Re-run the workspace 100-page count for a user (debugging)
```sql
SELECT count(DISTINCT workspace_id) FROM todos WHERE user_id = '<uuid>';
```
Should match `WorkspacePage.todos.length`-aware behavior in the app.

### Reset a user's monthly grant cycle (admin)
```sql
UPDATE user_subscriptions
SET next_grant_at = now()
WHERE user_id = '<uuid>';
-- then call the monthly-token-grant Edge Function (cron will pick it up within the hour)
```
